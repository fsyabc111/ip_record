# 运行、采集、存储与 Module 设计

状态：v1.0设计已封版，应用未实现；用户已确认的选择见 [decisions.md](decisions.md)。平台事实及官方来源见 [技术研究](../research/macos-feasibility.md)。

## 1. 进程、安装和生命周期

- 一个原生应用进程，Bundle ID 固定为 `local.fsy.iprecord`，应用名 `IP Record.app`。
- 部署目标为当前 macOS 27／arm64，Swift 6 严格并发检查。无需为未承诺的旧系统引入兼容分支。
- SwiftPM 分开 Swift target 与官方 C target；打包脚本建立标准 `.app`，捆绑 XDB、manifest、许可证并签名。最终应用不引用源码目录、不带 Python、不下载构建时未固定版本的依赖。
- 固定安装于 `~/Applications/IP Record.app`，避免注册临时构建路径。正常 LaunchServices 启动复用同一应用；另以用户数据目录锁阻止从命令行直接启动第二个写入实例。
- 每次主动重新打开已有应用仅显示当前弹窗；后台登录启动不抢焦点。历史／设置窗口分别复用一个，关闭不退出。
- 清晰区分用户暂停、机器睡眠、故障停止检查和明确退出；没有自动重启进程的 watchdog 或 helper。
- 暂停偏好持久化；退出不改变登录启动设置；下次登录若仍处于暂停则只显示暂停图标。
- 登录启动优先 `SMAppService.mainApp`。注册／注销都读取系统实际状态，并展示需批准／失败；不循环覆盖系统选择。
- 自动注册签名不被接受时，退路是系统设置手工添加固定路径应用；UI 明确进入系统管理模式，不能凭 `SMAppService.status` 宣称知道手工项状态。

## 2. 数据采集范围

| 数据 | 来源与合同 |
| --- | --- |
| 路径状态 | `NWPathMonitor`；`satisfied/unsatisfied/requiresConnection`，不等价于互联网可达 |
| 本机地址 | `getifaddrs`；接口、地址族、地址、作用域、可知前缀和启用状态；释放系统链表 |
| 接口类型／主接口 | 公开系统接口信息及每族 Global IPv4/IPv6 配置；无法确定则保留未知 |
| 网关 | SystemConfiguration global/service 的公开 Router 字段；带地址族、接口和来源 |
| DNS | Global／相关 Service 的公开服务器、搜索域和匹配域；始终声明配置覆盖可能不完整 |
| 代理 | `SCDynamicStoreCopyProxies` 的允许字段投影；HTTP/HTTPS/SOCKS、PAC/WPAD、例外 |
| 公网地址 | 分别向 `https://api.ipify.org` 和 `https://api6.ipify.org` 发 HTTPS 请求 |
| 归属地 | 本地 ip2region v3.18.0 双族 XDB；国家、省／地区、城市、组织、国家代码 |

不扫描附近 Wi-Fi、不读取 SSID/BSSID，不检查浏览器代理，不把 shell 的 HTTP_PROXY 当作系统代理。不开启定位、抓包、Network Extension 或特殊网络权限。

`NetworkSnapshot` 每个配置项包含 `readStatus=available/notObserved/unavailable` 和来源；DNS 另含 `coverage=partial`。空数组／缺少字典不自动等于“关闭”或“无法联网”。

## 3. 调度和检查轮次

默认间隔 300 秒，定时器可容忍约 30 秒合并唤醒；设置可选 300／900／1800 秒。它是清醒期间的检查目标，不是硬实时 SLA。无定时唤醒、无逐秒计数、无开窗额外轮询。

触发原因：首次开始记录、定时器、系统网络变化、系统配置变化、唤醒、恢复、手动检查、存储故障恢复。多原因合并为一个集合；原因本身不等于值得新增历史。

### 单轮算法

1. 所有触发进入同一 RecordingEngine。系统事件去抖 2 秒，连续抖动最长等待 10 秒后采集当前可见配置；最多一个轮次在途。
2. 读取规范化本机快照并确定网络上下文版本。与上轮不同立即使旧公网结果失去“当前已确认”资格；UI 可先展示本机新状态和待确认状态。
3. 路径不可用时跳过公网请求，保存最终本机状态；路径可尝试时，v4/v6 最多各一个并发请求。
4. 每族返回独立终态。正在检查不进入变化指纹；一族失败不取消另一族成功。
5. 提交前重读上下文／核对版本；过期轮次取消，旧公网值不得覆盖新上下文。失败轮次不回填假地址。
6. 查本地归属，计算状态指纹，交给 HistoryStore 事务处理；只有成功提交才推进“已保存状态”。
7. 下一轮按完成时间重排，不追赶过去的定时 tick。网络事件／唤醒与定时／手动重叠时合并，不重复请求。

点击“立即检查”时已有轮次就加入该轮，不建立并行请求；完成后 10 秒内再次点击只显示刚完成结果并提示时间。网络上下文发生真实变化不受手动冷却限制。

网络／配置事件引起的公网请求另有30秒最短启动间隔，防止反复切换造成请求风暴；冷却期间仍保存发生变化的本机信息，将新上下文公网标为待确认，只保留一个待补查任务。用户手动检查可提前要求一次，但仍受在途合并与10秒手动冷却约束。稳态定时与故障重试不绕过该约束。

事件 epoch 与配置内容指纹是两个不同值：相关系统变动回调入口通过线程安全计数器先递增 epoch，再去抖采集，不能等异步 actor 消息排队后才递增。开始读取前、读完快照、请求完成、提交前和发布当前状态前都核对 epoch；A→B→A 即使内容指纹最终相同，也不能接受旧 epoch 的请求。重复无效通知可以重查，但不因此新增变化记录。
轮次始终携带自己的上下文标识，不在返回时套用“此刻最新上下文”。提交后若刚收到变化事件，只能将刚写入值视为上一上下文记录，立即失效当前确认并调度新检查，不发布为新网络当前地址。

多个系统接口的读取并非原子快照，公网两族检查也不同时完成。每次保存采集开始／结束时间和每族请求时间；只能保证“该读取窗口未收到相关变化通知，且前后可见配置一致”，不能保证捕获没有通知的全部瞬态切换。读取失稳则丢弃该轮公网结果，不标成当前确认。

连续切换导致没有稳定上下文时，最长去抖到期后只保存“网络变化中”的可见本机配置／状态，明确 `snapshotConsistency=unstable`，公网未确认；事件重新安静后再检查，不无限堆积任务，也不把失稳快照称为同一时刻的全机状态。

### 睡眠、暂停和退出

- `NSWorkspace` 的 willSleep／didWake：睡眠取消请求、使轮次失效、停止定时器；唤醒仅做一次去抖检查。
- 屏幕熄灭不等于机器睡眠，不因此停止记录。
- 暂停立即取消请求和后续采集，停止订阅采集事件／定时器；恢复重新订阅并检查。暂停不允许手动绕过。
- 已发出的回调在暂停／退出／上下文变化后必须经过版本检查，不能落盘成新状态。
- 明确退出先取消、停止调度、尝试短时提交退出信息并关闭句柄，然后退出。保存失败不能无限阻止退出。
- 休眠／退出通知可能来不及写入；重启根据未正常结束的 session 和最后检查时间标记空档，不伪造精确结束时间。

## 4. 公网请求合同

使用专用 ephemeral URLSession；不覆盖系统代理行为。明确设置 `urlCache=nil`、请求策略 `reloadIgnoringLocalCacheData`，发送禁止缓存的请求头；仅 ephemeral 不足以禁用内存缓存。若 metrics 表明本地缓存命中，不用该结果推进确认时间。
关闭 cookie storage／自动设置 cookie 和 credential storage。网络／代理上下文变化后重建会话，旧会话取消。

系统 TLS 信任校验沿用默认处理，不自建放行规则。HTTP／代理认证挑战不弹登录框、不收集或保存凭据；无法无交互完成时以认证需求错误结束本族查询，由用户在系统代理中处理。

- v4 endpoint 只接受 IPv4，v6 endpoint 只接受 IPv6；映射地址先归一化再核对族。
- 仅 HTTPS，正常系统 TLS 校验；拒绝自动跨目标重定向，不在失败时退回 HTTP。
- HTTP 必须为 200；流式读取响应最多 1 KiB，超限立即取消，不先完整下载再截断。
- 只允许首尾 ASCII 空白和一个标准 IP；HTML、JSON、多个地址、私网／回环／未指定／组播等都判非法响应。
- 请求超时 6 秒，resource 与完整单族任务目标上限 8 秒；外层取消约束、DNS/PAC 真实超时行为列早期验收。不能声称未实测的绝对墙钟保证。
- 不做密集失败重试、不调用未经核实的备用供应商；下一次正常触发重试。
- 查询服务不需要鉴权；不发送本机 IP 清单、配置、历史、设备名称或应用追踪 ID。
- 每个成功结果保存 endpoint ID、地址族、开始／完成时间和上下文版本；原始响应体不落日志。

错误分类：DNS、连接、TLS、超时、HTTP、认证需求、超长、非法地址、地址族不符、取消。取消／轮次过期不冒充网络故障；HTTP code 可留详情。真实 v6 不可达、代理不支持该目标、服务故障等均只能显示“IPv6 出口未确认”。

此设计不证明本机原生 IPv6，也不证明所有目标使用同一出口。只要请求遵循系统网络，代理对外采用其他地址族亦符合用户选择。

## 5. 地址与配置规范化

- 地址身份按二进制值、地址族和必要 scope 比较，不按字符串外观比较；IPv6 压缩写法变化不算地址变化。
- IPv4-mapped IPv6 归并到对应 IPv4 做比较和归属查询；原始表示可作为观测详情保留。
- 本机接口地址集去重、稳定排序；链路本地地址保留接口关联。相同数值出现在不同接口仍是不同项。
- IPv4 netmask 转前缀必须验证连续位；不能转换就未知，不编造前缀。
- 地址分类显式覆盖私网、ULA、链路本地、回环、文档、组播和未指定等测试用例；离线库不代替地址作用域判定。
- DNS 服务器保持原顺序；同 IP 在不同服务／匹配域分别保留。地址集排序不能套用到 DNS 优先顺序。
- 代理开关、host/port、PAC/WPAD、例外规则只取公开允许字段；不整体 dump 系统字典。
- 代理不保存认证账号／口令；PAC 只保存启用状态和移除 userinfo/path/query/fragment 的 origin。相同 origin 下路径或脚本变化不单独识别，出口变化仍由周期检查发现。
- 不记录 RSSI、流量计数等高频变化量，避免它们制造持续历史行。

## 6. 状态模型与变化判定

控制条件是三个独立维度：持久化的 `userIntent=recording/paused`、进程生命周期 `awake/sleeping/stopping`、存储健康 `ready/blocked`。只有 recording＋awake＋ready 才允许检查，不能用一个互斥enum让唤醒或故障恢复覆盖用户暂停选择。
面向界面的有效状态按“停止中→存储故障→用户暂停→睡眠→记录中”优先级派生；有存储故障时同时显示用户是否已暂停。UI 临时 `checking` 与这些维度分离。

每族结果：`confirmed / failed / skippedNoPath / notYetChecked / deferredCooldown`，附规范化错误类别（若有）和同上下文最近成功地址。`deferredCooldown`只在新上下文等待事件限频补查时使用，不是每次定时检查都会出现的状态。旧上下文／旧 session 成功值另存为“上次记录”，不参与当前确认。

变化指纹包含：路径终态、快照一致性、规范化接口地址／前缀、主接口、网关／DNS／代理安全投影及读取状态、每族最终查询状态／错误类别（HTTP额外含状态码）／已确认地址。

网络上下文内容指纹只含本机网络与配置，不含公网结果；可见内容变化或记录空档时建立新的context ID，重复采集复用同一ID。事件epoch独立递增以保护轮次，但重复通知不凭空制造新context或历史。

指纹不包含：检查中、检查时间、网络回调计数、错误描述中的动态文案、请求耗时、排序噪声、地区翻译／显示文案或数据库版本。数据库更新不凭空产生网络变化。

同值重复成功更新最近确认；同类重复失败更新最近检查，不新增行。由失败恢复成功即使 IP 一样也新增查询状态变化。DNS 变化且公网 IP 不变仍新增配置变化。

用户已确认独立生命周期标记：`appStart / pause / resume / sleep / wake / appExit / uncleanGap / storageGap`，默认显示并可筛选隐藏。每次状态转换最多一条，不算周期检查记录。
生命周期标记没有“当时已确认公网地址”，地址列为空，以 `previous_state_record_id` 可空引用上条状态；禁止将旧地址复制成新成功值。
暂停／睡眠／退出使活动状态记录关闭；恢复／唤醒／新 session 第一轮即使地址一样也建立新观测起点。系统事件写入是尽力而为，未正常退出／睡眠未落盘时不能补造精确起止时刻。

## 7. 本地归属 Module

- 捆绑当前已校验的 v3 XDB：v4 11,122,036 字节，v6 37,277,813 字节；合计约 46.2 MiB 磁盘，不等于常驻内存。
- 启动／首次加载先由 Swift 按应用固定可信清单验证 SHA-256 和长度；任何不符都在进入 C 前拒绝。清单固定在构建产物并随应用签名，不把下载文件自带的同源 hash 当作真实性证明。
- Swift 安全预解析有界的256字节头，明确只接受当前 v3、`runtimePtrBytes=4`、正确族、合理索引起止／对齐／文件边界；再调用 C 兼容性校验。不能让尚未检查的头字段进入 C 位移／指针运算。用流式哈希，不能为校验永久缓存全库。
- 采用官方同版本 C 文件读取器，一个串行所有者管理两族句柄；不跨线程共享 FILE 指针；每次查询按官方合同分配和释放 region buffer。
- 每次 `xdb_region_buffer_init(&region,NULL,0)` 使用自动分配模式；初始化成功后无论查询成功／失败均释放 buffer。只在成功且 value 有效时读取，length=0 为未命中，v3 长度上限65535；按明确长度严格UTF-8解码并复制为Swift值后释放，不使用无界strlen／String(cString:)。
- 错误返回类型，不把裸指针泄露给 UI。已检测的损坏文件不送入原生读取器；不宣称任意恶意／运行中被改写文件都由上游 C 实现保证安全。
- 缓存上限 128 个 `(地址, 数据库哈希)` 结果；地址或版本改变才重查，不另建长期地理缓存表。
- `country|province|city|isp|countryCode` 必须字段数匹配；`0`／空转 nil。无结果、字段缺失、库损坏三个情况区分。
- 一族库故障只影响该族归属；仍保存公网地址与故障状态，不悄悄启用在线归属查询。
- 历史保存原始归属字段和库哈希，不只存一串本地化展示文案。
- 第一版已确认随应用更新，不提供运行时在线数据库下载、导入任意文件或后台更新。构建时显式更新固定来源／版本／哈希并验证，安装时只替换应用 bundle，历史库不清除。

## 8. SQLite 模型和事务

运行数据位于 `~/Library/Application Support/local.fsy.iprecord/`。目录 0700，数据库及 sidecar 文件按当前用户限制权限；不是写到 app bundle、源码目录或当前工作目录。
设置使用固定 Bundle ID 的 UserDefaults；应用资源 XDB 留在 bundle，无需首次启动复制一份。

### 表和不变量

| 表 | 关键字段 | 约束 |
| --- | --- | --- |
| `app_sessions` | UUID、started_at_utc_ms、last_checkpoint_at、ended_at、clean_exit、启动时区 | 异常退出不伪造 ended_at |
| `history_records` | `INTEGER PRIMARY KEY AUTOINCREMENT` id、session_id、kind、首次观测 UTC ms／时区 offset／单调时钟、trigger 集合、context_id、signature、snapshot_json、schema_version、搜索投影 | snapshot 值在记录创建后不改写；ID 保证采集顺序，清空不重置sqlite_sequence |
| `history_records` 确认摘要 | last_checked_at、last_confirmed_v4_at、last_confirmed_v6_at、closed_at／close_reason | 只更新当前未关闭且指纹相同的记录；确认时间只有对应族成功才更新 |
| `current_state` | 固定 id=1、active_state_record_id 可空、完整最新状态及 per-family 时间、signature、最后持久化时间 | 每轮最多一行覆盖；该指针只指活动状态行，不指生命周期标记；UI“已保存”以提交成功为准 |
| `schema_migrations` | 版本、应用版本、执行时间 | 有序事务；不兼容新版本数据库不能降级覆盖 |

`snapshot_json` 使用有版本的 Codable 合同，包含接口／网关／DNS／代理投影、首次观测时的探测结果／请求时间、同上下文 lastKnown、上次网络值及归属快照。历史详情与JSON分开提供不可变 `firstObservation` 和可变 `confirmationSummary`，不能拿摘要改写首次探测开始／完成时间。

新记录的 lastKnown 和时间必须复制最新已提交的 `current_state`，不能从上一条不可变初始快照取旧时间。例如 T0成功A、T1重复确认A、T2失败：前条最近确认是T1，失败条的上次地址为A@T1，失败检查发生于T2，绝不显示A确认于T2或仍停留T0。

活动行关闭后不再更新确认摘要；生命周期行不接收确认时间。外键引用删除时置空，清空后不可留下失效状态指针。
常用筛选列为 kind、首次观测时间、v4/v6、国家／地区搜索投影；无需 FTS、ORM 或通用事件溯源框架。

每轮持久化为一个事务：校验 session／上下文 → 比较已提交指纹 → 新增变化行或更新当前确认摘要 → 更新 `current_state` 和 session checkpoint → commit → 发布已保存状态。失败 rollback，不推进已提交指纹。

写连接串行所有；历史查询／导出用独立只读连接，WAL 模式；`synchronous=FULL`、外键开启、busy timeout 1 秒。页数阈值做 checkpoint，无每秒维护任务。索引为 `id`、观测时间、kind、v4/v6；分页使用 id 游标，不用大 OFFSET。

启动先确认版本并检查基本可读性；损坏库不自动删除或覆盖。迁移前用 SQLite backup 生成一致性备份，失败不继续迁移；保留失败原件，不为了启动创建空历史掩盖问题。

### 保存失败

写入失败进入 `storageBlocked`，停止后续公网检查，保留最后已保存状态和至多一份未保存结果，UI 显示“无法保存记录”。用户可重试，或下个 5 分钟维护机会重试本地存储；不在故障中密集联网。
恢复后标记记录空档，重新采集；不补造故障期间缺失的状态。只读历史能读时仍可查看／导出。

### 清空与长期保存

长期保留，不自动裁剪历史。清空是用户明确确认后的单事务：先将 `current_state.active_state_record_id` 置空，删除历史行（历史内部引用 `ON DELETE SET NULL`）；保留当前状态、设置和离线库。当前 session 设置 `historySuppressedUntilChange`，下一次真实变化或生命周期标记起点开始新增历史，新 session 也重建观测起点；同值重复检查只更新当前摘要，不把刚清空的历史立即填回。
该操作不宣称安全擦除磁盘残留。导出／历史查询与清空的并发由读事务快照处理，正在导出的文件保留导出开始时的数据范围。

## 9. 时间、导出和隐私

- 存 UTC 毫秒、观测时区 offset、session ID 及进程内单调时间；ID 为历史先后顺序权威，不能单凭墙钟排序。
- 时钟跳变不产生假“负持续时间”；用顺序和观测标签展示。切换时区不改数据。
- CSV 为单条历史一行，提供 UTF-8 BOM、标准引用／转义和公式起始字符防护；v4/v6、各族状态、确认时间、归属字段分列，本机地址／配置为明确摘要。
- CSV固定列组：record/session ID、kind、首次观测UTC与offset、最近检查、v4/v6各自地址/状态/最近确认/国家/省/市/组织/endpoint、各族归属库hash、本机地址、网关、DNS、代理安全摘要、触发原因；空档行地址列留空。
- JSON 为所选历史的完整有版本快照，包含筛选条件、导出时间、原始 UTC、firstObservation、confirmationSummary和各配置来源；不夹带范围外的当前状态或应用设置。CSV 不承担无损恢复功能。
- 导出明确选择当前筛选或全部；用户选定保存路径之后才建立只读快照，后台每批最多500条流式写临时文件，成功原子替换目标；失败／取消不留下看似完整的目标文件。
- 最多一个导出任务，始终可取消；读事务最长120秒，超时关闭读者并删除本次临时文件，提示缩小日期范围重试。避免长读者无限阻止WAL回收，不把用户停留在文件选择框的时间计入读事务。
- 用户确认系统文件覆盖操作；导出不包含口令、PAC 全 URL、脚本或 app 调试堆栈。
- 无遥测、账号、同步、在线地理查询。只调用用户知情的公网 IP 探测服务；本机配置和历史不上传。
- 日志只含固定事件、错误类别及必要技术码；不输出 IP、DNS／代理配置或 HTTP 原始响应。磁盘与性能诊断由用户手动导出。
