## 2. 开发早期的停止线

正式界面和完整历史功能之前先完成有限原生验证；失败先处理路线，不继续堆功能。

| 门 | 检查 | 通过标准／退路 |
| --- | --- | --- |
| G01 构建 | CLT＋SwiftPM、C target、app 打包、签名、资源读取 | Finder 启动，读取捆绑双库；无源码路径依赖；失败先修工具链／打包 |
| G02 菜单窗口 | NSStatusItem、popover、键盘、辅助功能、窗口焦点、正常重复打开 | 单图标，完整复制，关闭窗口继续运行；popover 交互／资源不合格用标准 NSMenu 摘要退路 |
| G03 原生归属 | Swift→C、双族、空结果、长 UTF-8、已检测的缺失／截断／损坏库 | 正确释放资源、无主线程阻塞；不加载未通过完整性检查的数据 |
| G04 增强快照 | 当前实际 Wi-Fi／有线／虚拟接口及可见网关、DNS、代理 | 来源可追踪，无法读取时未知；不要求改变用户日常网络以伪造测试覆盖 |
| G05 公网检查 | 用户当前实际网络、系统代理行为、单族失败、取消／超时 | 无跨上下文覆盖；服务失败如实显示；真实代理切换只在用户方便时验证 |
| G06 登录启动 | 固定安装路径、注册状态、用户系统禁用、真实重新登录 | 只有重登录实际启动才能通过；注册失败可用系统手工管理退路，不擅自退出用户会话 |
| G07 基础资源 | 最小原生应用和C文件模式、关闭窗口后稳态 | 记录CPU/RSS/文件读量，与预算比较；过重先减少UI常驻内容，不转Python常驻 |

这些门可以有降级通过，但必须记录采用哪个退路、用户体验变化及真实未测项。不得把手工系统登录项的存在伪装成自动注册成功。

## 3. 核心场景矩阵

| ID | 输入／场景 | 应有行为 |
| --- | --- | --- |
| A01 | 首次主动打开 | 一次说明、预选登录启动；开始后记录；以后后台不弹窗 |
| A02 | 同地址、同配置连续1000次最终成功 | 不新增变化行；每族最近确认正确推进 |
| A03 | IP不变，仅DNS／网关／代理投影变化 | 新增配置变化，保留完整来源；不伪造IP变化 |
| A04 | 地址列表仅枚举顺序改变 | 不新增变化；DNS优先顺序真实变化仍记录 |
| A05 | 公网v4变化、v6不变 | v4变更记录，v6确认独立；地区按各族查询 |
| A06 | v4成功、v6超时 | v4正常，v6出口未确认，不显示“无IPv6” |
| A07 | 仅公网v6成功 | v4未确认，IPv6折叠行明确已获取，可完整展开复制 |
| A08 | path satisfied但HTTP403／DNS／TLS失败 | 公网查询失败，不写成整机断网；本机配置仍保存 |
| A09 | 路径不可用但本机仍有地址 | 不请求公网，本机地址保留；上次公网仅作历史 |
| A10 | 网络A请求未返回，切换到B后A才返回 | A结果不能覆盖B当前状态或冒充B出口 |
| A11 | 网络A→B→A、事件风暴／枚举过程切换 | 轮次版本检查，旧结果失效；不只比较最后相同hash就接受旧结果 |
| A12 | 定时／唤醒／事件／手动重叠 | 合并单轮，最多每族一个逻辑在途请求，无请求队列堆积 |
| A13 | 同类失败连续发生，之后原IP恢复 | 重复失败不堆行；恢复新增状态变化；确认时间不在失败时更新 |
| A14 | IPv6多种等价写法、scope和映射IPv4 | 等价地址不产生假变化；不同接口scope不混；复制完整 |
| A15 | 多接口、多IPv6、虚拟接口、无主接口信息 | 摘要有稳定顺序；完整列表可达；不把en0硬编码为Wi-Fi |
| A16 | 归属地只有国家或省，没有城市／组织 | 省略缺失值，详情说明；不显示0／null／伪造城市 |
| A17 | 归属库一族缺失／校验失败 | 对应归属未知／不可用，另一族和IP历史继续；不自动调用在线地理查询 |
| A18 | PAC URL含凭证／路径token，配置读取失败 | 不落原始敏感URL；失败不冒充代理关闭 |
| A19 | 多作用域DNS、split DNS、本机DNS代理 | 显示系统配置和来源，partial说明；不声称真实上游 |
| A20 | 单族响应地址族错、HTML、超长体、重定向 | 拒绝，记录明确失败；不把响应当地址，不能绕过TLS |
| A21 | 暂停时请求返回、退出再登录仍暂停 | 旧请求不写入；不发新探测；暂停偏好保留 |
| A22 | 睡眠跨过多个周期，之后唤醒 | 睡眠无主动探测，不补追所有tick；醒后仅一次检查 |
| A23 | 退出／崩溃／强制关闭后再次启动 | 新观测起点；上次数据不当作当前成功；异常空档时间不伪造 |
| A24 | 改系统时间／时区 | 顺序按record id；无负持续时间；原UTC和offset保留 |
| A25 | 写磁盘失败／DB忙／迁移失败／数据库损坏 | rollback、不虚报已存；故障停止探测；保留原库，恢复后标记空档 |
| A26 | 清空取消／确认、清空与检查并发 | 取消无变化；确认原子删除历史，保留当前／设置／归属库；不会立即重复灌回旧历史 |
| A27 | 导出过程中取消／磁盘满／清空历史 | 临时文件处理正确，成功文件为一致快照，无半成品误导；CSV转义与公式防护 |
| A28 | 国外地名含逗号、引号、非ASCII、长IPv6 | UI完整可读，复制和导出不损坏；CSV/JSON可重新解析 |
| A29 | 10万条历史查询／筛选／滚动 | 有限分页，首屏预算通过，不全量加载，无UI主线程SQL |
| A30 | 关闭全部窗口、重复双击、直接执行第二个二进制 | 正常运行单图标；数据目录锁阻止双写；关闭窗口不停记录 |
| A31 | 系统撤销登录项、注册失败、重新安装应用 | 显示实际状态，不循环重注册；手工模式明确，不重复添加 |
| A32 | 记录进程退出后观察网络活动 | 不再由应用进行探测；没有helper继续记录 |
| A33 | T0成功A、T1同值成功、T2失败 | 旧行summary最近确认T1；新行lastKnown=A@T1、failed@T2；首次快照不被summary改写 |
| A34 | 配置不变但返回HTTP缓存命中／认证挑战 | 缓存结果不能更新确认时间；认证不弹框，不保存口令 |
| A35 | XDB哈希／长度／头字段或族不匹配 | 进入C前拒用；不因自带manifest也给出相同hash就当可信 |
| A36 | 接口每3秒变化、持续数分钟 | 本机变化按去抖采集；事件公网请求最短30秒，无队列堆积；待确认不复用旧出口 |
| A37 | 保存面板停留／导出超120秒／重复点导出 | 保存面板期间无读事务；一个导出；取消／超时关闭读者释放WAL约束并移除临时文件 |
| A38 | 已暂停后睡眠唤醒／存储故障恢复 | 用户暂停意图不被唤醒或修复覆盖，不开始探测；故障和暂停可同时说明 |

## 4. 测试方法和真实覆盖

- 状态机和变化判定使用可控时间、网络快照、延迟／乱序探测结果，验证上述不变量；不把UI私有实现作为测试合同。
- 存储测试使用临时真实SQLite，验证事务、中断恢复、只变化追加、当前摘要更新、迁移和导出一致性。
- 归属测试使用固定版本真实XDB与少量已知样例；损坏测试在副本上完成，不改正式下载文件。校验通过不等于地理准确性验证。
- 真实网络只检验实际执行过的环境。未具备的IPv6、网线、VPN组合明确未覆盖，不能用fixture冒充真实网络通过。
- 休眠／重新登录是用户可感知操作，实施前选择合适时机；不为验收擅自让用户退出会话。
- 不修改日常DNS／代理制造结果；需要真实配置切换时另行安排，使用可恢复的测试方案。
- 本轮只检查设计文档，无应用测试、登录项修改或探测服务调用。

## 5. 性能和稳定性测量

正常模式：窗口全部关闭、稳定网络、5分钟间隔，持续至少30分钟；报告真实请求数、采集轮数、CPU、RSS和磁盘／WAL增长。包含首次加载与稳态，不能只报最低瞬间。

另测：历史窗口打开、10万条合成记录、反复展开复制、连续查询失败、接口事件风暴、睡眠唤醒。合成历史只证明界面和存储规模，不是实际运行天数。

进程内存／句柄在合理循环后应趋于稳定；有持续增长先找泄漏，不通过设置“定期自动重启”掩盖。
资源预算见 [runtime-and-data.md](runtime-and-data.md)。若超标，报告测量条件和差距，再调整实现／批准预算变化。

## 6. 分步开发与提交

1. 设计封版：已解决本轮产品问题，完成文档交叉检查，记录未执行的真实验证。
2. 原生最小验证：G01–G07；先证明构建、采集、双栈、资源、菜单和登录路线。
3. 核心记录：调度、状态、SQLite、空档与故障处理，接口层验证关键不变量。
4. 产品界面：菜单、历史、设置、复制／导出／清空，进行真实交互验收。
5. 完整本机验证：实际网络、睡眠、重新登录、长期资源；生成可追踪报告。

每个有意义的实现／修复阶段小步提交推送；只提交本任务文件并检查敏感数据。用户已创建远程仓库 `https://github.com/fsyabc111/ip_record.git`，初始目标分支为 `main`；首次建立项目基线后，后续继续沿明确的分支跟踪关系提交推送，并验证本地与远程提交一致。推送不等于合并或发布。
